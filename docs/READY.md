# Критерии готовности 10.0

| Критерий | Как проверяется | Статус |
|---|---|---|
| Тесты и проверка кода зелёные на каждом коммите | `.github/workflows/ci.yml`: ruff, pytest на Python 3.11–3.13, `node --check` панели | автоматически |
| Чистая установка на Debian, Ubuntu, Fedora, Arch | CI, задача `packages` ставит зависимости в контейнерах дистрибутивов | автоматически |
| Docker за 5 минут без правки файлов | `docker compose -f compose.ghcr.yml up -d`, первый владелец — по коду из журнала | вручную при релизе |
| Паритет чата и панели | `tests/test_parity100.py`: у каждого раздела панели есть команда в чате | автоматически |
| Обновление с любой 6.x | `tests/test_upgrade100.py`: state.json и homebot.db от 6.0 читаются без миграции; бэкап перед обновлением (6.5) | автоматически |
| Сломанный модуль не роняет бота | `tests/test_plugins100.py` | автоматически |
| 30 дней на сервере владельца без ручного вмешательства | `/doctor` чистый, нет ручных перезапусков в журнале systemd | идёт после установки 10.0 |

## Что 10.0 не делает с данными

Ни один ключ `.env` и `state.json` не удаляется и не переименовывается. Незнакомые ключи `.env` (опечатки или
параметры, которые больше не используются) `/doctor` показывает предупреждением с 9.3, удалять их или нет —
решает владелец.
